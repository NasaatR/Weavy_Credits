# Форматы данных WEAVY CREDITS

Версия 1.0.1 добавляет встроенный native.js: recipeRuns/nodeRuns читаются без ручного JSON-профиля. Ниже описаны общий импорт и дополнительные адаптеры. Нативный runId = `weavy:` + JSON([recipeId, nodeRun.id]); workspace определяется по данным файла. Поле native содержит исходные ID, даты начала/возврата и текущую модель как ориентир. Оно не является финансовым подтверждением.

Все поля ниже — **внутренний контракт расширения**, а не предполагаемые названия полей Weavy. Примеры искусственные; их цены не являются тарифами Weavy. В установленном расширении примеров нет.

## Импорт запусков

«Данные → Импорт JSON» принимает массив записей или объект `{ "schema": 1, "runs": [...] }`.

```json
{
  "schema": 1,
  "runs": [
    {
      "workspaceId": "example-workspace",
      "fileId": "example-file",
      "fileName": "Example workflow",
      "runId": "stable-example-run",
      "nodeId": "example-node",
      "nodeName": "Example node",
      "nodeType": "video",
      "model": "EXAMPLE MODEL — NOT A WEAVY TARIFF",
      "provider": "example",
      "version": "example-version",
      "createdAt": "2026-09-20T10:00:00Z",
      "updatedAt": "2026-09-20T10:00:30Z",
      "status": "completed",
      "parameters": {"seconds": 5, "resolution": "1080p", "audio": true},
      "resultCount": 2,
      "previewCredits": 160,
      "source": "Example imported history",
      "events": [
        {"id": "example-debit", "kind": "debit", "credits": 150, "source": "Example ledger"},
        {"id": "example-refund", "kind": "refund", "credits": 50, "source": "Example ledger"}
      ]
    }
  ]
}
```

Обязательные строки: `workspaceId`, `fileId`, `runId`. Остальные данные могут отсутствовать. Отсутствующее число не заменяется нулём.

**Идентичность:** `workspaceId + runId` однозначно определяют запуск в нормализованных данных. Если реальные runId уникальны только внутри файла/ноды, адаптер должен заранее сформировать соответствующий составной стабильный runId. Один запуск с разными fileId помечается конфликтом, а не удваивается в объединённом отчёте. Retry получает отдельный runId только если источник действительно описывает отдельный запуск.

**Операции:** ID debit/refund должен быть уникален в пределах workspace. Повтор той же операции не меняет сумму. Один ID операции в разных запусках или с разными суммами делает расход неизвестным до выяснения. Один debit может относиться ко всем результатам запуска; нельзя копировать его на каждый output. Если источник даёт только cumulative charge, адаптер должен определить его семантику: меняющиеся snapshots нельзя представлять независимыми операциями или одной якобы неизменяемой receipt.

**Исторические параметры:** duration, seconds, resolution, quality, count, audio, inputTokens, outputTokens, width, height, fps, steps, mode, inputCount. Другие поля отбрасываются. Нельзя подавать состояние ноды вместо снимка запуска. Противоречивые значения одного запуска блокируют тарифную оценку. При наличии непротиворечивого debit реальное списание сохраняет приоритет.

`status` для оценки должен быть completed/succeeded/success. Неизвестные статусы сохраняются, но автоматически не оцениваются. Ошибка/отмена может иметь реальный дебет и возврат, поэтому не обнуляется без доказательства.

Фактическое число: сумма debit минус refund. Избыточный возврат или возврат без исходного debit даёт «без оценки». `previewCredits` никогда не включается в итог. Строки чисел автоматически не приводятся к числам при импорте: обработку единиц и формата должен подтвердить адаптер.

`fileUrl` необязателен: допускается только `https://app.weavy.ai/...`; query и hash отбрасываются. Если маршрут требует query/hash, такой сценарий пока не поддержан. Обычно ссылку можно явно связать с текущей страницей в отчёте.

## Каталог тарифов

Принимается массив тарифов или `{ "schema": 1, "rates": [...] }`. Повторяющиеся ID в импорте или совпадающие с существующим каталогом отклоняются целиком, пользовательские цены не перезаписываются.

```json
{
  "schema": 1,
  "rates": [
    {
      "id": "example-rate-v1",
      "model": "EXAMPLE MODEL — NOT A WEAVY TARIFF",
      "label": "Example linear seconds",
      "provider": "example",
      "version": "example-version",
      "unit": "second",
      "rate": 30,
      "base": 0,
      "minimum": 0,
      "step": 1,
      "divisor": 1,
      "multiplyBy": null,
      "components": [],
      "conditions": {"resolution": "1080p", "audio": true},
      "validFrom": "2026-09-01T00:00:00Z",
      "validTo": null,
      "source": "Synthetic documentation example; verify actual Weavy price",
      "checkedAt": "2026-09-22T00:00:00Z"
    }
  ]
}
```

Единицы: `run`, `result`, `second`, `inputTokens`, `outputTokens`, `inputCount`. Исторический интервал `[validFrom, validTo)`. Если подходит несколько тарифов — стоимость неизвестна; расширение не выбирает случайную цену.

Каждый компонент: `ceil(units / step) × step / divisor × rate × multiplier`. Итог: `max(minimum, base + сумма компонентов)`. Основной компонент задан верхними полями, до 8 дополнительных — в `components`. У всех компонентов могут быть `unit`, `rate`, `step`, `divisor`, `multiplyBy`.

`multiplyBy` — null / resultCount / count / inputCount. Применяется только явно. Нет данных о множителе — нет оценки. Двойное умножение на результаты следует исключить при составлении тарифа.

Пример LLM: основной inputTokens, rate=2, divisor=1000; дополнительный `{ "unit":"outputTokens", "rate":5, "divisor":1000, "step":1 }`. Это искусственные цифры для описания механизма, не цены провайдера/Weavy.

Неизвестные имена условий отклоняются, чтобы не потерять платный параметр молча. Нелинейные тарифные диапазоны можно представить отдельными конфигурациями только при однозначных условиях; произвольные формулы/удалённый код не выполняются. Если реальное правило невозможно выразить, оставьте стоимость неизвестной до доработки механизма.

Денежные настройки не являются модельными тарифами: `USD = credits × usdPer10k / 10000`, `RUB = USD × rubPerUsd`. `null` означает «не настроено», 0 — явно введённое значение. Внутренний расчёт не округляется.

## Адаптер

Это механизм для разработчика после получения реального образца. **Не используйте пример ниже как готовый адаптер Weavy:** пути, поля и endpoint в нём вымышлены и используются только как fixture теста.

```json
{
  "id": "example-fixture-only",
  "name": "Example fixture — NOT VERIFIED FOR WEAVY",
  "origin": "https://app.weavy.ai",
  "pathPrefix": "/fixture-not-a-real-api",
  "itemsPath": "items.*",
  "enabled": false,
  "evidence": "Synthetic fixture only; replace after source verification",
  "statusMap": {"done": "completed"},
  "fields": {
    "workspaceId": "$.workspace",
    "fileId": "workflow",
    "runId": "execution",
    "nodeId": "node",
    "model": "model",
    "createdAt": "started",
    "updatedAt": "updated",
    "status": "state",
    "parameters.seconds": "params.seconds",
    "resultCount": "outputsCount",
    "previewCredits": "preview",
    "debitId": "charge.id",
    "debitCredits": "charge.credits",
    "refundId": "refund.id",
    "refundCredits": "refund.credits"
  }
}
```

`itemsPath` с `*` раскрывает массив. Пути `fields` относительно элемента; `$.` — относительно корня ответа. ID workspace/file/run обязательны именно из ответа: текущая страница не подставляется, чтобы поздний ответ не попал в чужой файл. Один простой mapping извлекает до одного debit/refund на элемент. Для сложного ledger/нескольких операций могут потребоваться отдельный адаптер или нормализованный импорт. JSON-механизм не претендует на покрытие ещё не исследованной схемы.

Разрешены HTTPS-домены weavy.ai; endpoint не вызывается, только сопоставляется с уже пришедшим ответом. MAIN-скрипт должен быть на app.weavy.ai. Редирект продукта на иной домен потребует обновления манифеста и проверки.

## Хранение и границы доверия

IndexedDB хранит версию схемы 1. Неизвестная будущая версия отклоняется. Запись снимка состояния атомарна; worker сериализует конкурирующие сообщения. При ошибке запись не подтверждается. Лимит состояния — примерно 40 МБ по длине JSON; импорт до 50 000 записей, чтение файла до 40 МБ, диагностические схемы — последние 40. Старые запуски автоматически не удаляются. Текущая реализация рассчитана на умеренные истории; весь снимок состояния читается при изменении.

Страница не может менять настройки, тарифы, импорт или резервные копии через мост. Новая диагностика также содержит обезличенные примеры разрешённых параметров/статусов и текущие цены. Входящая структура диагностики очищается повторно в worker. Число сообщений ограничено; при слишком интенсивном потоке возможны пропуски, поэтому полнота не заявляется. Если схема перестанет совпадать с адаптером, запуск не будет придуман.

Названия файлов/нод и ID сохраняются, поскольку нужны для отчёта. Резервная копия может содержать эти рабочие названия: это не обезличенная диагностика. Не отправляйте её вместо файла диагностики без необходимости.


## Уточнения модели в отчёте (1.4.0)

Полная резервная копия содержит `modelAssignments`: объект из стабильного составного ключа и выбранного названия модели. Ключ генерации — JSON-массив `["run", workspaceId, fileId, runId]`. Ключ ноды — `["node", workspaceId, fileId, nodeId, исходнаяМодель]`; последнее значение приведено к каноническому алиасу и нижнему регистру, либо пусто при отсутствии модели. Модель ноды не применяется к её генерациям с другой исходной моделью.

С версии 1.4.0 общий ключ названия — `["name", нормализованноеИсходноеНазвание]`. Название берётся из исторической модели, сохранённой модели для оценки или подсказки модели; для ручного уточнения при их отсутствии допустимо имя ноды. Известные алиасы, регистр, разделители и нули в конце версии приводятся к одной идентичности; отличающиеся версии и варианты сохраняются раздельно. Общее уточнение действует во всех файлах и рабочих пространствах, включая будущие записи.

Приоритет: уточнение генерации, затем уточнение ноды, затем общее уточнение названия. Установка общего уточнения удаляет прежние уточнения соответствующих нод, сохраняя исключения отдельных генераций; общая отмена возвращает прежние настройки. Сброс только общего уточнения не удаляет отдельные исключения.

Уточнения не меняют исходные `model`, `native.estimateModel`, параметры и операции списаний. Они участвуют только в тарифной оценке. При наличии debit/refund их сумма имеет приоритет. Резервные копии до 1.3.0 допустимы без `modelAssignments`. В CSV есть отдельные колонки `assignedModel` и `assignmentScope`.

В 1.5.0 сравнение уточнений совместимо с прежними ключами названий и нод после исправления разделителей/версий. Установка и сброс общего выбора убирают его прежние эквивалентные ключи; отмена сохраняет прежние значения. Несогласованные варианты одного нормализованного правила не выбираются автоматически. Уточнение запуска без `nodeId` не удаляется при установке общего выбора.

Модель результата хранится в `native.outputs[].model`. Если все выходы известного количества содержат одну эквивалентную модель, расчёт может использовать её как историческое свидетельство, не переписывая исходный `run.model`. Более точный именованный вариант может уточнять общую модель каталога. Разные модели либо модель только у части выходов требуют ручного уточнения; технические ноды не становятся расходами по метаданным загруженной картинки.

Диагностика `analysis` и файл проверки расчёта включают `coverage`: число неизвестных записей/диапазонов и группы проблемных моделей с причинами, количеством записей и похожими названиями. В `records[].outputs` включена модель результата, в `records[].cost.source` — источник оценки. Идентификаторы и названия проектов по-прежнему исключены из этого аудита; полная резервная копия сохраняет рабочие данные.
